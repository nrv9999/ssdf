## Rep-date design (decisions)
- `df.flow_rep_dttm` keyed by flow point id = current per-point state (dttm, rep_id, id_batch). `df.flow_rep_dttm_clc` KEPT (user insisted: multi-tier destination readiness needs it) = per-batch contribution journal. `df.vw_dest_rep_dttm` = destination-stage watermark: min over builders, null until all reported.
- Rep date is generated by StrtF points only (function returning timestamp); other points inherit min over deps' watermarks. The max(rep_date)-from-loaded-data refinement was removed by user. `df.exec_id` upserts own flow_rep_dttm row AND inserts clc contribution unconditionally (incl. on error).
- StrtF dest = the sa-level LOAD PROCEDURE it feeds (e.g. `dwh.uf_sa_wait_contact_collection_event -> dwh.usp_sa_load_contact_collection_event`); the load targets the sa-table (tier 2) and depends on the StrtF point via (procname, 'f').
- `--no-rep-dttm` / `_use_rep_dttm=false`: watermarks still WRITTEN, only excluded from closure/propagation math (batch points only). On full runs from StrtF the flag changes nothing; user doubts its necessity (PLAN.md candidate).

## Execution architecture
- Original SQL path: `df.exec_flow` closure (tmp_plan_list over vw_flow_1 + watermarks) → batch_log plan → `df.exec_batch_from_id` wave walker (tmp_exclude error propagation; tmp_next/tmp_next_filter with vw_ordr_max gate); dbms_lock serializes everything; pg_cron schedules waves (+2 min).
- Python dispatcher `framework/python/ssdf.py` (psycopg3): client threads instead of cron; all logic SQL ported verbatim; `df.exec_id` still called as SQL (CALL returns OUT _strt_dt); `pg_advisory_lock(hashtext('ssdf_exec_batch_from_id_lock'))` held ONLY around batch_log state transitions — exec_id outside the lock → real parallelism; claim (executed='running') replaces find_free_job; dbg messages preserved; get_for_resource/wait_for_resource hooks kept.
- vw_ordr_max intent (user): try to launch the whole next level; resource shortage leaves tails (хвосты); return to them at the next level; an available next-level point with higher priority than a tail goes first. Current walker cannot do this (finisher sees pending at own level → no walk; deferred points never picked up) — implement together with max_parallel_points (PLAN.md item 2).
- psycopg3 gotcha: same named param in `is null` + cast contexts → DatatypeMismatch; cast EVERY occurrence (%(x)s::type[] is null).

## Fault handling (user taxonomy)
- User SQL-workload errors: handled by `df.exec_id` itself (WHEN OTHERS → exec_log error → propagation). Nothing else automatic.
- System faults (network drop, server reboot, dispatcher crash): closed MANUALLY via admin tools — Python `framework/python/ssdf_admin_clean_err_tail.py` (interactive: numbered running list, 0=all, empty=cancel; naming ssdf_admin_<action>, more may come) + SQL `df.list_running()` / `df.close_running(int[])`. Closure: batch_log.executed='error', _sqlerrm='system fault'; phantom running exec_log rows closed too, real done/error history preserved. Closure does NOT propagate/continue the batch (flagged to user).

## Install design
