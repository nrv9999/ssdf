# ssdf — контекст для ассистента

В начале сессии прочитай `.memory/MEMORY.md` и файлы, на которые он ссылается: там состояние работы, принятые решения и текущий план. Раскладка памяти: `.memory/MEMORY.md` и `.memory/project/ssdf-dev-state.md` — в git (теория/дизайн, без машинной «кухни», репозиторий публичный); `.memory/project/ssdf-local-machine.md` — untracked (игнорируется через `.gitignore`), свой на каждой машине: локальная БД, развертывание, прогоны. План работ — `PLAN.md` в корне (в git).

Кратко: PostgreSQL-фреймворк ETL (схема `ssdf`) + demo-поток (схема `smpl_dwh`), локальная БД `demo` (PG 18, расширения dblink / pg_cron / pg_background / pg_dbms_lock). Пользователь ведёт дизайн и последовательность работ; команды с sudo отдавать ему в терминал (shell — fish). Рабочие таблицы процедур именуются `tmp_*`. Не коммитить без просьбы.
